# Sources

No skill loads this file. It records where each practice in `frie-core` comes from, so a rule can be checked against its source when it is questioned. A rule listed under Preferences is Brandon's own choice and needs no source.

The "Stated in" column gives the file and section. `SKILL.md`, `architecture.md`, and `testing.md` are the three files of the `engineering-patterns` skill.

## Stricter than mainstream practice

Brandon chose the stricter form of each rule here on purpose, because the reader is a code agent. The note gives the mainstream position and then the strongest dissent. Each source was read in November 2026 unless the note says a position is cited from memory.

|---|---|---|---|

PEP 8 says consistency within a project is more important. For a style-guide recommendation, though not for a requirement, Google allows a deviation when local inconsistency would confuse readers. |
| A rule yields only where the language or a framework dictates the shape, and a habit of the ecosystem is not a dictate | `SKILL.md`, Intent over form | PEP 8: https://peps.python.org/pep-0008/ | A style guide is normally applied with judgment. ## Contested in the field
